## 2023-10-24 - stream=True defeats requests.Session pooling
**Learning:** Using `stream=True` with `requests.Session()` to avoid downloading large bodies on soft-404s causes the connection to be dropped instead of returned to the pool if the body isn't fully consumed. The latency cost of repeated TLS handshakes for subsequent paths heavily outweighs the bandwidth saved from not downloading the HTML, making this an anti-pattern.
**Action:** When using `requests.Session()` for repeated calls to the same host, either use `stream=False` to automatically consume the body and reuse the connection, or explicitly consume `r.content` to ensure connection pooling works.
