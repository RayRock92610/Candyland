💡 What: Added WAL, MEMORY temp_store, and NORMAL sync pragmas to `scripts/kessel`, and created `idx_queue_recipient_status` index on the `queue` table.
🎯 Why: Polling the local state queue caused massive disk I/O locking and full table scans since there was no index on `recipient` and `status`, leading to severe performance degradation as `COMPLETED` records accumulated.
📊 Impact: Reduces daemon polling time from ~1.08s to ~0.0003s per poll (O(N) full table scan reduced to O(log N) index lookup), and significantly lowers SQLite write-lock latency.
🔬 Measurement: Run the new test script in `.jules` or see the dramatic CPU drop during standard `kessel run` loads.
